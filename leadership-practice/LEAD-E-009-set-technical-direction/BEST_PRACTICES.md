# LEAD-E-009 — Set technical direction

## Best practices

- Start with the subsystem’s user and organizational outcomes, not a preferred technology.
- State a quarter-plus horizon, current constraints, non-goals, and a small set of strategic bets.
- Translate direction into guardrails and sequenced initiatives that independent teams can apply.
- Publish the memo before alignment meetings so review focuses on disagreements and missing evidence.
- Name leading indicators, invalidation signals, and a review cadence rather than presenting direction as permanent.
- Keep portfolio-level direction distinct from a single architectural decision and its alternatives.

## Four habits

1. Maintain one discoverable direction memo per key subsystem.
2. Link each proposed initiative to a named strategic bet or guardrail.
3. Collect written dissent and assumptions before synchronous alignment.
4. Review direction quarterly or when an invalidation signal crosses its threshold.
